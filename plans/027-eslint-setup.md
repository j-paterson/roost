## Why this matters

The repo has **no linter at all** — only `tsc` with `strictNullChecks` + `noImplicitAny`
(NOT full strict, and crucially **no `noUnusedLocals`**, so `tsc` never flags dead
imports/vars). Throughout the recent decomposition work, dead imports left behind by
refactors were invisible to the typechecker and had to be caught by hand-grepping. A
linter with even a tiny rule set closes that gap permanently and gives future
contributors automated feedback.

This plan is deliberately **minimal and additive**. The goal is to *establish the ESLint
harness* with a handful of genuinely high-signal rules — NOT to lint-gate CI, NOT to
mass-fix the codebase, NOT to enable the full `typescript-eslint` recommended preset
(which would bury real signal under hundreds of stylistic warnings on a mature codebase).
Expanding the rule set and fixing violations are explicit follow-ups for later plans.

## Scope

**In scope (the ONLY files you may create/modify):**
- `eslint.config.mjs` (NEW — flat config at repo root)
- `package.json` (add devDeps + one `lint` script line)
- `package-lock.json` (regenerated by `npm install`)

**Explicitly OUT of scope — do NOT touch:**
- Any `.ts` / `.tsx` source file. **You introduce ZERO source changes.** If the linter
  reports violations, you do NOT fix them by editing source. (You may only adjust
  `eslint.config.mjs` rule severities to keep the baseline clean — see Step 4.)
- `tsconfig.json`, `vite.config.*`, `.github/` / CI config (no CI gate in this plan).
- `tests/e2e/**`, `scripts/promo/**` (these use wdio/Playwright globals and bespoke
  setups — they are in the ignore list, not linted).

## Environment / isolation (READ FIRST)

This plan **adds devDependencies**, so your worktree needs its OWN real `node_modules`

user's actual `node_modules`). The orchestrator will hand you a worktree based on
`960199f` with **no** `node_modules` symlink. Run a real `npm install` in it (Step 3).

Verification commands assume repo root = your worktree root.

### Step 3 — Install (real install, isolated worktree)

```

```

if it is, STOP and report the conflict rather than forcing it). `package-lock.json`

### Step 4 — Create `eslint.config.mjs` (flat config)

Create `eslint.config.mjs` at the repo root with EXACTLY this content:

```js
// Minimal, high-signal ESLint flat config. Deliberately NOT the full
// typescript-eslint recommended preset — see plans/027-eslint-setup.md.
// Type-aware linting is intentionally OFF (no parserOptions.project) to keep
// `npm run lint` fast and config-light. Expand the rule set in a follow-up.
import js from "@eslint/js";
import tseslint from "typescript-eslint";
import react from "eslint-plugin-react";
import reactHooks from "eslint-plugin-react-hooks";
import globals from "globals";

export default tseslint.config(
  {
    // Global ignores — keep this first.
    ignores: [
      "dist/**",
      "node_modules/**",
      "**/*.js",
      "**/*.mjs",
      "**/*.cjs",
      "tests/e2e/**",
      "scripts/promo/**",
      "coverage/**",
      "main.js",
    ],
  },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    files: ["**/*.{ts,tsx}"],
    plugins: { react, "react-hooks": reactHooks },
    languageOptions: {
      globals: { ...globals.browser, ...globals.node },
      parserOptions: { ecmaFeatures: { jsx: true } },
    },
    settings: { react: { version: "19.0" } },
    rules: {
      // --- high-signal, repo-specific value ---
      // tsconfig has no noUnusedLocals; this is the rule that catches the dead
      // imports/vars that tsc silently allows. Warn (not error) so it never
      // breaks the build, but it shows up in `npm run lint`.
      "@typescript-eslint/no-unused-vars": [
        "warn",
        { argsIgnorePattern: "^_", varsIgnorePattern: "^_" },
      ],
      "react-hooks/rules-of-hooks": "error",
      "react-hooks/exhaustive-deps": "warn",
      "no-debugger": "error",

      // --- intentionally relaxed: this codebase's established patterns ---
      // App logs intentionally; many any-casts are deliberate interop seams.
      "no-console": "off",
      "@typescript-eslint/no-explicit-any": "off",
      "@typescript-eslint/no-empty-object-type": "off",
      "@typescript-eslint/no-unused-expressions": "off",
      "react/react-in-jsx-scope": "off", // React 19 + automatic runtime
      "react/prop-types": "off", // TS handles prop types
      "no-undef": "off", // TS handles undefined-symbol detection
    },
  },
);
```

> Note: `tseslint.configs.recommended` is mostly `error`-level. If, after Step 5, the
> baseline shows **error-level** violations that are clearly established-pattern noise
> rather than real bugs (e.g. `@typescript-eslint/no-require-imports`,
> `no-case-declarations`, `prefer-const`), you MAY downgrade those specific rules to
> `"warn"` or `"off"` by adding them to the `rules` block above — **adjusting config only,
> never source.** Document every rule you relax and why in your report. The target end
> state: `npm run lint` runs to completion and any remaining `error`-level findings are
> genuine, small in number, and listed in your report (NOT fixed here).

### Step 5 — Run the linter, capture the baseline

```
npm run lint
```

`eslint` exits non-zero if there are any error-level findings (warnings alone do not
fail it). Capture the full summary line (e.g. "✖ 142 problems (3 errors, 139 warnings)").
Then break it down:

```
npx eslint . -f json | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const r=JSON.parse(s);const by={};let e=0,w=0;for(const f of r)for(const m of f.messages){const k=m.ruleId||'(parse)';by[k]=(by[k]||0)+1;if(m.severity===2)e++;else w++;}console.log('errors',e,'warnings',w);console.log(Object.entries(by).sort((a,b)=>b[1]-a[1]).slice(0,25))}"
```

Report the error count, warning count, and the top rules by frequency. This baseline is
the deliverable — it tells the maintainer what a future cleanup pass would address.
